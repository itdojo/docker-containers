# frigate — working notes

## Decisions

- 2026-08-16: Profile selection is `COMPOSE_FILE` in `.env`, not `-f` flags. Compose reads that key out of `.env` itself, so `docker compose up -d` stays the command on every host and the per-host choice lives in the one file that is already per-host.
- 2026-08-16: Ports live in a swappable overlay (`compose.ports.yaml` / `compose.wireguard.yaml`) rather than in the base. A service using `network_mode:` cannot declare `ports:`, so the WireGuard variant has to remove them, and removing an inherited key needs the `!reset` tag — see "Ruled out".
- 2026-08-16: Image pinned to `0.17.2`, not `stable`. On an NVR the symptom of an unwanted upgrade is footage you do not have. `FRIGATE_IMAGE` is a variable because the correct tag differs by arch: plain on amd64 and Pi, `-standard-arm64` on generic arm64 like Gateworks Venice.
- 2026-08-16: Mosquitto is unpublished. Frigate reaches it as `mosquitto:1883` on the project's default network, so nothing needs to leave the host. `allow_anonymous true` is only defensible because of that, and `mosquitto.conf` says so at the point where someone would change it.
- 2026-08-16: No custom `networks:` block. Both services sit on the project default network, which is what lets the WireGuard overlay set `network_mode: service:wireguard` on Frigate without a conflicting `networks:` key inherited from the base.
- 2026-08-16: `config.yml.example` ships all five detector blocks with four commented out rather than splitting them into includable fragments. Frigate has no include directive — it reads exactly one config file. Same reasoning as mediamtx shipping its auth block commented.
- 2026-08-16: WireGuard scoped to split tunnel, reaching remote cameras. `AllowedIPs` lists camera subnets only; the UI stays on the LAN and no `go2rtc.webrtc.candidates` change is needed. The full-tunnel case is documented as a trap, not supported as a configuration.
- 2026-08-16: `compose.wireguard.yaml` is the DEFAULT network overlay, not `compose.ports.yaml`. The real deployment ingests from LAN cameras and tunnel cameras simultaneously, and the sidecar already serves both — split tunnel means `wg-quick` installs routes only for the `AllowedIPs` prefixes and the namespace keeps its ordinary default route out through the Docker bridge. A host with no remote cameras switches to `compose.ports.yaml` and never creates a `wg0.conf`.
- 2026-08-16: Mixed ingest needs no marker in `config.yml`. Local and remote cameras are configured identically and every camera path is `127.0.0.1:8554` anyway, because they all read the go2rtc restream. Routing is `wg0.conf`'s job; the LAN/tunnel grouping in the example is a comment, not a mechanism.
- 2026-08-16: Substream guidance reversed for Pi 5 camera hosts. The earlier "dual stream is not optional" was written from the Frigate host's point of view. A Pi 5 has no hardware encoder, so a `-sub` path costs it a software decode plus a second software encode; at one or two cameras per Pi that buys nothing. Publish one 720p stream and give the single input both roles. The split still earns its keep across the tunnel, where the detect stream is pulled continuously over a link whose bandwidth is not ours.
- 2026-08-16: `frigate-setup.sh` seeds `wireguard/wg0.conf` from the example rather than only complaining it is absent, since the default profile now requires one. It seeds at mode 0600 and still fails the run — the file is a template, not a working tunnel.
- 2026-08-16: Theme block in `frigate-setup.sh` is `sed -n '62,344p'` of `mediamtx-users.sh`, which is itself a verbatim copy of `~/projects/qol/linux/base_functions.sh`. Copied whole. A partial copy is a restyle.

## Gotchas

- **`network_mode` and `ports` are mutually exclusive in Compose.** This is the entire reason the base file publishes nothing. Putting ports back into `compose.yaml` breaks the WireGuard overlay with an error that names neither file.
- **A detector overlay and `config.yml` name the detector independently, and nothing reconciles them.** A mismatch starts cleanly, loads the wrong detector and detects nothing. `frigate-setup.sh` exists mostly for this one check; it greps for uncommented `type:` lines and compares against the overlay named in `COMPOSE_FILE`.
- **Frigate 0.17 replaced `record.retain`.** Retention is now `record.continuous.days`, `record.motion.days`, and separate `alerts`/`detections` blocks. A config copied from any 0.15-era guide will not load, and the error does not say "this key moved".
- **Raspberry Pi 5 has no hardware H.264 decoder.** The block was removed from the SoC; Frigate's presets stop at Pi 3/4. There is no `/dev/video11` to mount and `preset-rpi-64-h264` is wrong there. This is why `compose.rpi.yaml` is a Pi 4 file and why the substream configuration matters more on a Pi 5 than anywhere else.
- **The Raspberry Pi AI Camera is not a Frigate detector.** It is a Sony IMX500 doing inference on the sensor; Frigate has no path to that output and treats it as an ordinary camera. Only the M.2 Hailo module works with `type: hailo8l`.
- **A Coral USB re-enumerates after firmware upload** — `1a6e:089a` cold, `18d1:9302` warm, on a new bus path. Mount `/dev/bus/usb` wholesale; a mount of the node it had at startup vanishes underneath the container.
- **`DNS =` in `wg0.conf` breaks MQTT.** It rewrites `resolv.conf` for the whole shared namespace, so Frigate stops resolving `mosquitto` and reports a broker failure that looks nothing like a DNS problem. The example ships it commented with that explanation attached.
- **`AllowedIPs` is a routing table, not an ACL.** `0.0.0.0/0` installs a default route inside the namespace and simultaneously kills LAN cameras, the Mosquitto connection, and the return path to a LAN browser on 8971. `frigate-setup.sh` warns on it.
- **A prefix in `AllowedIPs` that overlaps a local subnet silently captures it.** Far-end LAN and near-end LAN both on `192.168.1.0/24` is the common collision; the local cameras stop answering the moment the tunnel comes up while the remote ones work perfectly, so the tunnel is the last thing suspected. An overlap with Docker's bridge pool presents as an MQTT failure instead. `check_allowedips_overlap` compares against `ip -o -f inet addr` (minus `lo`/`wg`/`tun`/`tap`) and every Docker network's IPAM subnets, and hard-fails. Overlap math is integer compare after masking both prefixes to the shorter length.
- **Restarting the WireGuard sidecar destroys Frigate's network stack.** Docker does not restart the dependent container. Frigate has to be bounced afterward; `depends_on` does not cover this. With mixed ingest this is worse than it first looks — it takes LAN cameras and the UI down too, not just the remote cameras.
- **A Raspberry Pi 5 has no hardware video encoder at all.** BCM2712 kept an HEVC decoder and dropped everything else, including the H.264 encoder the Pi 1–4 all had. This is why a Pi 5 mediamtx host should publish one modest stream rather than a main plus a `-sub`: both encodes would be software, competing with the camera capture on the same cores.
- **`set -e` plus `pipefail` turns a missing command into a silently-skipped check.** `_local_subnets` began with `ip -o -f inet addr show | awk ...`; on a host without iproute2 the pipeline returned non-zero, `set -e` aborted the whole function before it reached the Docker subnets, and `check_allowedips_overlap` then compared against an empty list and printed PASS. A check that passes because it did not run is worse than no check. Every source in that function is now individually tolerated with `|| true`, and the caller counts how many networks it actually compared — zero produces a warning, never a pass. Same trap applies to any check added later.
- **The qol theme block emits `/dev/tty: Device not configured` on stderr when there is no TTY.** `_term_cols` does `stty size </dev/tty 2>/dev/null` — the redirect suppresses `stty`'s stderr but not the shell's failure to open `/dev/tty`. Harmless (it falls back to 80 columns and the fallback is correct), invisible interactively, and visible in captured output. The fix belongs upstream in `~/projects/qol/linux/base_functions.sh`, not here — do not patch the local copy.

## Ruled out

- **`ports: !reset []` in a WireGuard override.** Would have kept ports in the base file. Rejected 2026-08-16: the Compose version that introduced `!reset` could not be confirmed from the docs, the tag has open handling bugs (docker/compose#10697, #12162), and this folder has to run on hosts whose Compose is whatever their vendor image shipped. The overlay split costs one more filename and has no version floor.
- **A separate `go2rtc` container.** Frigate bundles it. A second one would mean two processes pulling the same cameras.
- **A reverse proxy for TLS.** Frigate's own nginx already terminates TLS with authentication and role-based access on 8971. Adding Caddy or Traefik would put a second TLS layer in front of a working one.
- **`hwaccel_args` as an `.env` variable.** It belongs to ffmpeg in `config.yml`, and `auto` is correct on nearly every host. Promoting it to `.env` would imply it is a per-host setting that must be set, which it is not.
- **A custom `healthcheck:` on the Frigate service.** The upstream image defines its own, and shipping a second one written against unverified internals would report failure on a healthy container.

## Constraints

- One folder, copied as-is to a Pi 4, a Pi 5, a LattePanda Delta or Sigma, or a Gateworks Venice board. `.env` and `config/config.yml` are the only files edited on the target.
- Cameras arrive as RTSP from mediamtx (`~/projects/docker-containers/mediamtx/`), typically on separate hosts. Frigate is the consolidation box, not the camera host.
- Recordings go to external storage. SD-card recording is called out as a wear failure, not a preference.
- Filenames stay lowercase-hyphen; the setup script follows the qol house style (`~/projects/qol/script-design.md`) and the IT Dojo terminal design system.

## Open questions

- Whether the mediamtx side should grow a documented substream path convention (`<name>` / `<name>-sub`) so the two repos agree by contract rather than by README prose. Now narrower than it was on 2026-08-16 morning: the convention is only wanted on camera hosts that can encode twice cheaply, which excludes the Pi 5s. Possibly the mediamtx side should instead document a default publish resolution suitable for detection.
- Whether a Pi 5 mediamtx host should publish HEVC rather than H.264, given BCM2712 kept the HEVC decoder. Would not help the Pi (it is encoding, not decoding) and would cost the Frigate host, which has no HEVC path on most of the fleet. Probably not, but it has not been measured.
